# FaceID 6.1.0 implementation plan

Goal: make people, photo search and chronological camera history the everyday workflow, preserve recognition behavior, and prepare a permission-preserving Access1 integration.

Architecture: extend the existing Gallery, AuditStore and FastAPI application. Store bounded face samples per event in the existing audit database; similarity is evidence, never an identity assignment or access grant. Reuse the React shell, existing enrollment and clip APIs.

Constraints: preserve existing slugs and data; no automatic enrollment from search; no guessed Access1 API, permissions or synthetic success events. Access1 must authorize the mapped user at the mapped reader and record its own biometric result. Its actual API/version is pending user clarification.

- [x] Harden Unicode identities, assignment races, MQTT startup/callbacks, atomic backups, add-on option serialization and propagation; add regression tests before changes.
- [x] Extend AuditStore with bounded normalized face vectors, retention cleanup and chronological paginated identity/similarity queries. Tests: multi-camera, unknown faces, duplicate samples, pagination, date filters, wrong dimensions, invalid vectors, explicit labels.
- [x] Add photo search with explicit face selection, gallery matches, source-specific timelines, indexing of retained historical evidence in a background job, no enrollment side effects. Test endpoints with actual Gallery/AuditStore and a deterministic face engine.
- [x] Add reusable face explorer, upload-to-search, enrollment handoff, known/unknown timelines and simpler daily navigation. Keep expert tools under disclosure; verify phone and desktop layouts.
- [ ] Implement Access1 against supplied documentation; until available expose only an honest disabled setup state and persistent user/camera mapping preparation, never an unlock endpoint pretending to enforce remote permissions.
- [ ] Set version 6.1.0, document limitations, synchronize add-on source/assets, run backend tests and frontend build, review diff, publish to r11a/faceid and create v6.1.0 release after CI passes.

Ruling: execute inline without additional approval checkpoints per the user's AGENTS instructions. Existing checkout has an unrelated deleted test; use an isolated worktree from origin/main. Native worktree creation could not resolve the project container, so git worktree is used.
