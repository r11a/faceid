FaceID 6.7.2 — installation, validation and rollback

1. Back up the current FaceID add-on and its persistent data in Home Assistant.
   Keep the previous complete operational package. Do not unpair, delete users,
   remove mappings, restore a different gallery or replace persistent /data.
2. Replace the existing local add-on's source files with source/faceid-addon
   from this package. Keep the existing local add-on slug/location. Do not
   install a second instance over the same data directory.
3. Refresh the local add-on repository and install/rebuild version 6.7.2.
   A restart alone does not rebuild an image. Confirm the update/build succeeds.
4. Open FaceID and hard-refresh once. Confirm 6.7.2 in the add-on, UI and
   diagnostics report. Verify gallery, pairing and camera/person mappings.
   No CPU/provider, identity or liveness settings are automatically changed.

Calibration: no Access1 request is generated by these actions
- Open Cameras, select the intended camera and save its observation source.
- Frigate restream uses the configured camera restream. Direct RTSP uses its
  saved, validated private-network URL. Both use the existing shared reader.
- Snapshot mode preserves the previous preview selection. Its displayed image
  is not necessarily the event-specific cropped snapshot used for association.
- The picture refreshes while visible. Enable the face-size measurement button
  only when needed. Measurements and boxes refer to the displayed measured frame.
- Source unavailable/busy is explicit; there is no hidden fallback to another feed.
  A new stream may take a few refreshes to pass startup/freshness checks.
- Diagnostic admission is global single-flight. At most one calibration camera
  has a renewable lease. Unused leases expire within roughly 5–10 seconds; a
  camera switch may briefly show busy while the previous lease retires.
- Measurement is detector-only, low priority, with a bounded scheduler wait.
  Recognition can continue. Closing/hiding the screen stops future polling;
  an already executing native model call completes normally.

Automatic recognition configuration
- For restream/direct mode, recognition is explicitly event-driven. It still
  needs a Frigate person event and an unambiguous event-to-face association.
- Local-network trust must be explicitly enabled before stream evidence can
  authorize access. Calibration does not enable trust or change saved settings.
- Access requires confirmed liveness and valid identity/source/deadline checks.
  For an access camera, inspect liveness mode/model readiness and the progress
  toward at least three valid same-person samples. Merely seeing 'recognized'
  from continuous-camera history does not establish access eligibility.
- Continuous sightings and old recordings/clips are not promoted into live
  Access1 evidence. Keep existing Access1 permissions, policies and mappings.

Short full-chain commissioning guide (separately authorized rig use)
1. Verify the exact source, trust, recognition mode and liveness settings after
   save + reload. Ensure Frigate sees person events for that camera.
2. Open the retained acquisition/recognition diagnostic window and start the
   passive full-recognition capture for that camera/source.
3. During an approved face approach, expect one event timeline containing:
   trigger -> anchor/stream -> subject association -> three valid samples ->
   recognition -> Access1 submission -> final Access1 result.
4. Download the full capture JSON and save the matching FaceID logs. Report the
   perceived delay, number of people, and whether the actual relay changed.
   Do not send camera URLs/passwords or gallery data.
5. Compare 20 matching ordinary approaches on snapshots and the selected stream.
   Record success count and median/p95 event-to-relay latency. Exercise bystanders,
   crossings, departure, reconnect and duplicate-event cases. No threshold lowering.
   Acceptance target: >=19/20 ordinary successes, improved median/p95 versus the
   comparable baseline, and zero wrong-person/duplicate activations in these tests.

The normal connector can act while diagnostics are open. To perform a genuinely
non-actuating field test, use an explicitly isolated test rig/inhibition procedure;
opening this page does not pause automatic access. Development tests were offline.

Failure interpretation
- timestamp_nonprogressing: decoder timing was rejected; calibration cannot cure it.
- anchor metadata/header failure: event association cannot be established. Keep
  safeguards and inspect the report. The existing Frigate header contract remains.
- liveness_unconfirmed: identity alone is insufficient for access.
- evidence_not_live: archival evidence was correctly blocked before submission.
- calibration_busy/recognition_busy: diagnostics yielded to bounded work.
- source_changed: profile or reader generation changed while measuring; retry.

Rollback
Select Existing snapshots, save, reload and confirm the effective profile; review
the desired snapshot recognition mode explicitly. This retains pairing/gallery.
For full software rollback, restore the previous complete operational package and
rebuild/reinstall it, or use the Home Assistant backup. Never delete /data to roll back.
